# 可信性能测量工具链

## 这个工具解决什么问题

本仓库的基准在 32 核共享实例上运行，**单次采样噪声可达 3~7 倍**。
在引入这套工具之前，性能结论是这样得出的：

> 跑 21 次同批交错取均值+中位数 → 报告「degrade 收益 +140%」

这个结论**无法复现**。独立复现的结果是 **+0.55%**。原因是：采样没有
A/A 对照，无法知道噪声带有多宽；而"先跑基线、后跑改动"的顺序本身
就能造出 **+50%** 的假差异（见下）。

本工具链的作用：**在给结论之前，先证明你的测量方法能分辨出这个结论。**

## 四步工作流

```bash
# 0. 构建被测程序（以 C 边基准为例）
cd test/bench/cbench
clang -O2 -std=gnu11 -D_POSIX_C_SOURCE=200809L -I ../../../build/include \
      -o bench_c main.c ../../../build/lib/libkaula_runtime.a -lpthread -lm

# 1. 标定：拿同一个二进制跑 A/B，测出本档位的噪声带
python test/bench/perf/calibrate.py \
    --exe test/bench/cbench/bench_c --curve degrade --conc 100 --rounds 41
#    → 产出 test/bench/perf/baselines/degrade_100.json
#    → 关键产出：detectable_min_pct（该档位能检出的最小真实差异）

# 2. 规划：查「要检出 X% 的差异需要多少轮」
python test/bench/perf/plan_samples.py --curve degrade --conc 100 --target-detect 3.0

# 3. 对照：拿两个二进制做 A/B，得到机器判定
python test/bench/perf/compare.py \
    --a <基线exe> --b <改动exe> --curve degrade --conc 100 --rounds 76

# 4. 退出码可直接接入 CI
#    0 = 无差异/改善   1 = 退化   2 = 疑似（需复测）/数据未收敛
```

## 判定规则（compare.py）

四类互斥结论：

| 结论 | 条件 | 含义 |
|---|---|---|
| **无差异** | 95% CI 跨 0 **或** \|效应量\|<0.147 | 统计上不可区分 |
| **疑似** | 检验显著，但 \|中位差\| < 可检测下限 | 方向可信、幅度未定型 → 加大轮数复测 |
| **改善** | 检验显著且幅度超阈值，符号为正 | 真实改善 |
| **退化** | 检验显著且幅度超阈值，符号为负 | 真实退化 |

**「无差异」与「疑似」必须分开。** 早期版本把三个条件用「或」连起来，
结果一个 p=0.0002、CI=[-6.8%,-1.7%] 的**真实退化被报成「无差异」**——
这是最危险的漏报方向（把退化藏起来）。见下方灵敏度验证。

## 灵敏度验证（工具自身的测试）

工具的失效模式是「漏报退化」，所以必须用**已知的假退化**验证它。

| 注入 | 理论退化 | 轮数 | 工具判定 | 是否正确 |
|---|---|---|---|---|
| DEGRADE_SPIN 20000→22000 | −9.09% | 21 | 无差异 | 漏报（噪声吃掉） |
| 同上 | −9.09% | 61 | 疑似（p=0.0002） | 方向正确 |
| 同上 | −9.09% | 76 | 见 `compare` 输出 | — |

**结论：本机 degrade/100 档位在 21 轮下检不出 9% 的退化。**
必须按 `plan_samples.py` 的建议加大轮数。这是机器的物理限制，
不是工具缺陷 —— 工具的价值正是**把这个限制量化并暴露出来**。

## 各文件职责

| 文件 | 职责 |
|---|---|
| `stats.py` | 统计原语：bootstrap CI、Mann-Whitney U、Cliff's delta。**带 17 项自测** |
| `harness.py` | 采样器：交错执行、预热丢弃、正确性前置、超时强杀 |
| `calibrate.py` | A/A 标定：产出噪声带与可检测下限 |
| `compare.py` | A/B 判定：四类结论 + CI 退出码 |
| `plan_samples.py` | 样本量规划：反推所需轮数 |
| `baselines/*.json` | 标定结果（判定阈值的来源） |

## 为什么每个统计选择是这样的

| 选择 | 原因 |
|---|---|
| 中位数而非均值 | 采样分布右偏，均值被离群值拉高 |
| Mann-Whitney 而非 t 检验 | 不假设正态、对离群稳健、小样本可用 |
| bootstrap CI 而非 ±1.96σ | 样本小、有序列相关，正态近似不准 |
| Cliff's delta 而非只报 p 值 | p 值不回答"差异多大"；大样本下 0.1% 也能 p<0.001 |
| 交错执行 | 否则"先跑方吃亏"，实测可造 +50% 假差异 |
| 预热丢弃 | 首轮页表未热、频率未爬升，明显偏低 |
| checksum 跨轮一致性 | 把正确性与性能分开；算错了跑多快都没意义 |

## 自测

```bash
python test/bench/perf/stats.py --selftest     # 17 项，覆盖符号/边界/抗离群
python test/bench/perf/compare.py --a <exe> --aa --curve degrade --conc 100
#   ↑ A/A 自检：必须判「无差异」，否则工具本身有问题
```

## 使用纪律

1. **没有 A/A 标定的档位，`compare.py` 会用兜底阈值并打印警告 —— 该结论不可信。**
2. 报告性能数字时**必须同时给出**：轮数、CI、效应量、判定结论。
3. 判定为「疑似」时，**不要**对外声称改善或退化，按规划器加大轮数复测。
4. 单次运行的耗时随 `--conc`/`--total` 增长，规划器的耗时估算是保守值。
