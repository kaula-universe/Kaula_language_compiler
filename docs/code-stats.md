## 统计口径与方法

1. **tokei 标准口径**：有效代码 = 总行数 − 注释行 − 空行。tokei 默认跳过隐藏目录与 `.gitignore` 覆盖的文件；本次统计在干净克隆上进行，无构建产物干扰。
2. **`.kl` 补计**：tokei 12.1.2 不认识 `.kl` 扩展名。补计规则依据 `compiler/internal/lexer/lexer.go` 的词法实现校准：
   - `#` 与 `//` 为行注释（扫到行尾）；
   - `#[...]` 为属性注解，属**代码**而非注释；
   - `.kl` 无块注释（`/*` 在词法层直接报错）。
   - 判定顺序与 tokei 一致：空行 → 注释行 → 代码行（含行尾注释的行计为代码）。
3. **JSON 数据单列说明**：10 个 JSON 文件共 27,859 行，其中
   - `test/bench/service3/results*.json`（13,753 行）与 `test/bench/matrix.json`（3,925 行）为**压测测量数据**；
   - `compiler/stdlib.json`（10,090 行）为标准库清单/构建元数据。
   这些是数据与生成物，不是手写源码，故在"手写源码"口径中剔除。

## 复现方式

```bash
git clone https://gitee.com/kaula-universe/kaula.git
cd kaula
tokei . --sort lines                 # 标准口径
tokei . --hidden -e .git --sort lines # 含 .github 隐藏目录
```

`.kl` 补计脚本（与 tokei 同口径，注释规则经 lexer 源码校准）：按 git 追踪清单遍历 `*.kl`，空行 / `#`、`//` 注释行（`#[` 除外）/ 代码行三分类计数。
